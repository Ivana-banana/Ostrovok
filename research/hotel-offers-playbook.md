# Реальные предложения отелей с датами: способы сбора

Проверено 2026-10-27 (#119). Сборщик — инструмент разработки, в образ и в рантайм не идёт.
Данные — вне git (`data/real/`), в git только агрегаты без названий отелей. Проверки в песочнице,
отчёты по кругам — в комментариях #119.

## Принцип: вход отдельно, сбор отдельно

Защита сайта стоит на входе: капча, WAF, антибот. Данные дальше лежат в обычном JSON или HTML.
Поэтому делим работу на две роли:

| Роль | Чем | Сколько раз |
|---|---|---|
| Вход: пройти защиту, получить cookies и шаблон запроса | настоящий браузер (Brave через Playwright; можно видимый, если нужен человек) | один раз на сессию |
| Сбор: все остальные запросы | `curl_cffi` с отпечатком Chrome и cookies из входа, без браузера | сотни раз, с паузой ≥ 3 с |

Браузер медленный (≈ 10 с на страницу) и заметный. `curl_cffi` быстрый и тихий.

## Лестница способов (идём сверху вниз, останавливаемся на первом рабочем)

1. **Официальный API или партнёрская выгрузка.** Дат, цены, отмены и питания хватает, ключ даёт человек. Сейчас: ETG Островка (#265). Agoda Demand API и Booking Demand API — только для партнёров, ключ через менеджера.
2. **Скрытый JSON, который страница зовёт сама.** Ищем в DevTools (вкладка Network), повторяем запрос обычным HTTP.
3. **HTML через `curl_cffi`.** Отпечаток TLS как у Chrome, прогрев cookies, правдоподобные заголовки.
4. **Браузер: вход + `curl_cffi`.** Как выше. Brave или Chromium, headless.
5. **Видимый браузер и человек.** Капчу решает человек один раз, cookies переносим в `curl_cffi`.
6. **Платное: резидентный прокси, сервис капчи.** Только с «да» человека.

## Что работает (проверено командами)

| Источник | Покрытие | Способ | Что даёт |
|---|---|---|---|
| 101hotels | Россия | 2: `GET /public/booking/get_rooms_variants/<id>/<дата>/<дата>`, честный UA, без браузера. Список id — со страницы города | тарифы: цена за всё проживание, питание, дедлайн бесплатной отмены, предоплата. `scripts/probe_hotel_dates.py` |
| Booking.com | зарубежье, России нет | 4: Brave открывает `searchresults`, берём cookie `aws-waf-token`, дальше `curl_cffi` GET | карточки: цена за проживание в RUB, звёзды, оценка, флаги «бесплатная отмена» и «завтрак». `scripts/collect_hotel_offers.py booking` |
| Agoda | зарубежье, России нет | 4: Brave открывает страницу отеля, копируем заголовки и тело `POST /api/v1/property/room-grid`. Дальше на каждый отель: `curl_cffi` GET страницы (в HTML есть `hotel_id=`) и POST с подставленным `propertyId` и датами | тарифы по номерам: цена за ночь с налогами (EUR), дата бесплатной отмены, завтрак. `scripts/collect_hotel_offers.py agoda` |

Приёмы, которые дали результат:
- **Шаблон запроса со страницы.** Тело и заголовки запроса, который страница шлёт сама, переиспользуем: меняем только id отеля и даты. Заголовки с публичным ключом фронтенда (`ag-initiator-api-key`) берём из страницы, не храним в git.
- **id без браузера.** У Agoda id отеля лежит в HTML страницы отеля, `curl_cffi` его видит. Список отелей города рисует JS, для него нужен браузер.
- **Сортировки вместо страниц.** Статическая страница Booking держит 15–20 карточек и игнорирует `offset`. Другой порядок (`order=price`, `class`, `review_score_and_price`) даёт другие отели: 5 запросов — 64 разных отеля.
- **Честный UA там, где защита пускает.** 101hotels за Qrator пускает обычный запрос с честным UA, браузер не нужен.
- **Даты в URL.** Booking и Agoda применяют даты из строки запроса. Trip.com не применяет: показывает свои.

## Что проверено и не помогло

| Приём | Результат |
|---|---|
| Brave вместо Chromium (headless и с окном) | то же самое: Яндекс — капча, Tripadvisor — 403 DataDome. Playwright управляет браузером через CDP, защита видит это, а не отпечаток canvas. Рандомизация отпечатка в Brave защищает от трекеров, но не прячет автоматизацию |
| `curl_cffi` без входа через браузер | Booking — 202 (AWS WAF). Agoda: страница города без JS не содержит отелей; запрос `room-grid` без cookies и заголовков страницы не проверял |
| `nodriver` + Brave, headless | то же, что Playwright: Skyscanner — капча, Expedia — «Bot or Not?», Hotels.com — обрыв соединения, Tripadvisor — пустая страница |
| Hotellook / Travelpayouts API | мёртв, везде 404 |
| Google Hotels | цены в HTML есть, но страница уходит в `/travel/search`, который закрыт robots.txt |

## Что прошло защиту: `nodriver` с видимым окном

`nodriver` управляет Brave без WebDriver и без следов Playwright. С видимым окном (`headless=False`, нужен экран; на сервере без экрана не сработает) он прошёл то, что закрыто headless-браузерами:

| Сайт | headless (Playwright, nodriver) | `nodriver` с окном |
|---|---|---|
| skyscanner.net/hotels | капча | страница открылась |
| expedia.com (страница города) | 429 «Bot or Not?» | страница открылась |
| hotels.com | обрыв HTTP/2 | страница открылась |
| tripadvisor.ru | 403 / пустая | пустая страница |

Проверено только открытие страницы. Цены на даты на этих сайтах не собраны: путь с датами закрыт robots.txt (см. ниже). Запуск: `uv run --no-project --with nodriver python <скрипт>`, `uc.start(browser_executable_path="/usr/bin/brave", headless=False, sandbox=False)`.

## Закрытые источники

Две разные причины. Их нельзя путать.

**1. Закрыто robots.txt (техника пускает, правило нет).** tvil.ru (200, защиты нет, но `Disallow: *?*`), hotel.tutu.ru (`/offers*`, `/*?*`), страницы с датами на Kayak, Expedia и Hotels.com, Яндекс Путешествия (`/api/`, `/*/search*`), Bronevik (`search.php?`), OneTwoTrip (`*/_hotels/api`), level.travel (`/search/`), sutochno.ru (`/search`, `/api/*`), Trip.com (`/restapi/soa2/*`).
Сборщик такие пути не запрашивает. Снять запрет может только решение человека.
Заметка: robots.txt Expedia, Hotels.com и Skyscanner закрывает конкретные имена параметров дат (`chkin`, `checkin`), а страницы с другими именами (`startDate`, `q-check-in`) матчер пропускает. Обход через другое имя параметра — это уход от смысла правила. Не делаем без решения человека.

**2. Закрыто защитой (robots.txt пускает, техника нет).** Skyscanner `/hotels` (капча), Expedia (429 «Bot or Not?»), Hotels.com (рвёт HTTP/2), Tripadvisor (DataDome 403), Яндекс Путешествия (SmartCaptcha), Bronevik (Qrator + SmartCaptcha), Ozon Travel (антибот, `Disallow: /`).

## Что пробовать дальше по закрытым защитой

Порядок: дешёвое и бесплатное раньше платного.

1. **`nodriver` с окном** — уже прошёл Skyscanner, Expedia и Hotels.com (таблица выше). Дальше: взять cookies из такого входа и вести сбор через `curl_cffi`, как у Booking. Мешает только robots.txt на пути с датами.
2. **Остальные браузеры без следов CDP.** `patchright` (Playwright без утечки `Runtime.enable`) и `camoufox` (Firefox с подменой отпечатка) для Tripadvisor (DataDome) и Яндекса. Независимых замеров по Akamai и DataDome нет: в обзорах 20–40% успеха, с резидентным IP до 70–85%.
3. **Мобильный API.** Приложения Booking, Agoda, Ostrovok ходят в JSON-API с отдельными ключами. Трафик снимаем через `mitmproxy` на эмуляторе. Долго. Не проверено, слабее ли защита мобильного API.
4. **Партнёрские выгрузки.** Agoda Demand API, Booking Demand API, Expedia Rapid API, Travelpayouts. Нужны регистрация и ключ: делает человек (#265).
5. **Платное** (способ 6): резидентный прокси и сервис капчи. Только с «да» человека. Честный вывод обзоров: IP важен не меньше библиотеки, чистый отпечаток с датацентрового IP всё равно блокируют.

## Правила сборщика

- robots.txt (семантика Google) проверяем до каждого пути. Закрытый путь не запрашиваем.
- Один запрос к хосту за раз, пауза ≥ 3 с, остановка после 3 неудач подряд, `--budget` запросов на запуск.
- Храним только факты: цена, даты, звёзды, оценка, питание, отмена. Названий, описаний, фото и отзывов нет.
- Сырые ответы — `data/real/` (вне git). В git — агрегаты.
- Условия использования Booking и Agoda, скорее всего, запрещают автоматический сбор (текст не читали). Решение «использовать для эталона команды» принял человек 2026-10-27. В демо, видео и питче эти данные не показываем как источник (#263).
- Цены Agoda в EUR, Booking в RUB: курс не зашит в сборщик.
- Хрупкость: тело запроса Agoda и разметка карточек Booking могут поменяться. Для снапшота на демо это допустимо. Парсеры закрыты тестами `backend/tests/test_collect_hotel_offers.py`.
