# /hackathon-kickoff

Вход — рабочая папка планировщика: `<input>/_arch/` (solo) или `.arch/<run>/` (team).
Работа идёт в задаче «Kickoff: выход планировщика → репозиторий» (её заводит
`bash scripts/issues.sh bootstrap`) и в её worktree. Без задачи — стоп.

## Что куда

| Выход планировщика | Куда | Кто |
|---|---|---|
| `01-task-brief.md` | `CLAUDE.md`: задача, пользователь, критерии и веса, ограничения, «что запустит жюри», формат сдачи; его читает `submission-checklist` | скрипт |
| `00b-probe.md` | «Ловушки данных» в `CLAUDE.md`, `eval/traps.json`; тривиальный ответ — `eval/baseline.json` | скрипт |
| — | тест на каждую ловушку (id `TRAP-n` в тесте; `make check` это проверяет) | ты |
| `00c-domain.md` | `research/domain.md` | скрипт |
| `02-scenarios.md` | `eval/cases.json`; jury-click → `make e2e` | скрипт; проверки кейсов — ты |
| `02-scenarios-holdout.md` | `eval/holdout.tar.gz` + `eval/holdout.sha256` + `eval/final-log.md`; `builder` его не читает | скрипт |
| ADR | `docs/adr/`, `docs/decisions.md` D-001, пресет или стек с нуля в интерфейс `make` | скрипт; контракты — ты |
| `BUILD-PLAN.md` | план задач (`area:`, «Зависит от #…», приёмка по сценарию, сложность и модель, приоритет по cut line); вехи M0–M3, заморозка, cut line → `docs/timeline.md` | скрипт; Issues — после «да» |
| «What a jury will ask» | `pitch/QA.md`, режим «вопросы жюри» агента `jury` | скрипт |
| чего нет | `[СПРОСИТЬ]` в тексте и строка в `docs/questions-for-organizers.md` | скрипт и ты |

## Порядок

1. **Не читай `02-scenarios-holdout.md`.** Его запечатывает скрипт. Ты пишешь тесты и
   контракты — holdout в твоём контексте сделает их подогнанными.
2. Механика:

   ```bash
   python3 .claude/skills/hackathon-kickoff/kickoff.py apply --arch <папка планировщика>
   ```

   Скрипт пишет файлы, делает `git add` своих путей и печатает отчёт и план задач.
   Issues не заводит. Сеть не нужна.
3. Проверь вывод глазами: `CLAUDE.md` (блоки `kickoff:*`), `docs/timeline.md`,
   `eval/cases.json`. Ошибку разбора исправь руками в файле. Строку `Режим:` не трогай.
4. Пресет. `stack.mk` нет — `make setup PRESET=<из отчёта>`. Стоит другой — скажи
   человеку, не меняй сам. Пресет не подходит — свой `stack.mk` по контракту в `Makefile`.
5. Контракты по ADR: типы и форматы на границах модулей — в `contracts/` (или в месте,
   которое задаёт пресет: `src/<pkg>/contracts.py`, `web/src/contracts.ts`). У каждого
   контракта — README со списком потребителей и fixture в `tests/fixtures/`. Строка в
   `docs/decisions.md`, если формат — решение.
6. Тест на каждую ловушку из `eval/traps.json`: id ловушки в имени или комментарии.
   Тест падает на сырых данных-примерах и проходит после обработки. Нет данных — тест
   на fixture, который воспроизводит ловушку.
7. `eval`: в харнесе пресета заведи проверку для каждого критического кейса из
   `eval/cases.json`. Остальные кейсы харнес покажет как «не автоматизирован».
   `make eval` печатает baseline из `eval/baseline.json`.
8. e2e: сценарии `jury_click` — в сквозной тест (`make e2e`) на заглушке. Демо-путь
   жив с первого коммита.
9. `make check` и `make eval` — зелёные. Коммит, `bash scripts/finish.sh`.
10. **План задач — человеку.** Покажи таблицу из вывода скрипта. Допиши пустые
    `area:` и «[уточнить на kickoff]» в `<папка>/kickoff-plan.json`. Жди явного «да».
11. После «да»:

    ```bash
    python3 .claude/skills/hackathon-kickoff/kickoff.py issues --arch <папка> --confirmed
    ```

    Скрипт создаёт метки `area:`, затем Issues в порядке зависимостей и пишет номера
    в `kickoff-plan.json` (повторный запуск не дублирует).
12. Очередь `team.py` планировщика с этого момента не ведём: задачи — только Issues.

## Отчёт в чат

Что записано; пресет; ловушки и тесты на них; кейсы eval (автоматизировано N из M);
печать holdout (первые 12 знаков sha256); список `[СПРОСИТЬ]`; план задач и статус
Issues (не заведены / заведены #…).

## Нельзя

- Заводить Issues до «да» человека. Подтверждение плана — решение человека
  (`CLAUDE.md`, «Автономия»).
- Открывать holdout, печатать его в чат, переписывать печать.
- Придумывать то, чего нет в выходе планировщика: только `[СПРОСИТЬ]`.
